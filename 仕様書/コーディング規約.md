# Unity C# コーディング規約

## 1. はじめに

このドキュメントは、Unity開発におけるC#コーディング規約を定めたものです。クリーンで保守性の高いコードを書くことで、チーム開発の効率化と品質向上を目指します。

> 「クリーンなコードは、常に書いた人が配慮を込めて書いたかのように見える」  
> — Michael Feathers

## 2. チーム開発の原則

### KISS原則（Keep It Simple, Stupid）
- 可能な限りシンプルな解決策を選ぶ
- 不要な複雑さを避ける

### YAGNI原則（You Aren't Gonna Need It）
- 現在必要な機能のみを実装する
- 将来的に必要になるかもしれない機能は、実際に必要になってから実装する

### DRY原則（Don't Repeat Yourself）
- コードの重複を避ける
- 同じロジックは一箇所にまとめる

### その他の重要な原則
- **問題の根本原因を特定する**: 応急処置ではなく、根本的な解決を図る
- **継続的な改善**: 毎日少しずつコードを改善する
- **完璧より優秀**: 完璧を目指さず、プロダクションレベルで十分なコードを書く
- **一貫性の維持**: 決めたルールを継続的に守る

## 3. 命名規則

### 識別子の命名基準
- 特殊文字（バックスラッシュ、記号、Unicode文字）は避ける
- 略語は使用しない（数学的表現やループカウンタを除く）
- 意味のある名前を使用する

### ケーシング規則

#### PascalCase
以下に使用：
- クラス名
- インターフェース名
- public フィールド
- メソッド名
- プロパティ名
- enum 名と値

## 5. クラス設計

### クラス構成順序
1. Fields
2. Properties
3. Events / Delegates
4. MonoBehaviour Methods (Awake, Start, OnEnable, etc.)
5. Public Methods
6. Private Methods

### カプセル化
- 各クラスはPublicメソッドとインターフェイスを通じて値をやり取りする
- 内部処理を意識せず扱えるクラスを作る

### 単一責任原則
- 各クラスは一つの責任のみを持つ
- クラスが肥大化した場合は分割を検討

```csharp
// 悪い例：複数の責任を持つクラス
public class Player : MonoBehaviour
{
    // 移動、攻撃、UI、サウンドを全て処理
}

// 良い例：責任を分割
public class Player : MonoBehaviour
{
    private PlayerMovement m_movement;
    private PlayerCombat m_combat;
    private PlayerAudio m_audio;
}
```

### 疎結合
- 基本的にクラスは単に入力を受け取り、出力を行うというだけの設計にする
- 入力や出力を行うのがどのクラスであれ同じ結果を返す
- これにより変更に強くなり、クラス単位の単体テストが可能になる

## 6. メソッド設計

### 基本原則
- メソッドは小さく保つ
- 一つのことのみを行う
- 引数の数を最小限に抑える
- 副作用を避ける

```csharp
// 良い例
public void SetInitialPosition(float x, float y, float z)
{
    transform.position = new Vector3(x, y, z);
}

// bool を返すメソッドは疑問文形式
public bool IsTargetInRange(Transform target, float range)
{
    float distance = Vector3.Distance(transform.position, target.position);
    return distance <= range;
}
```

## 9. よくある問題とアンチパターン

- **謎めいた命名**: 意味不明な変数名やメソッド名

### 数学計算の最適化

#### 距離計算の最適化
```csharp
// 悪い例：平方根計算は重い
void CheckDistance()
{
    float distance = Vector3.Distance(transform.position, target.position);
    if (distance < attackRange) // 毎回√計算
    {
        Attack();
    }
}

// 良い例：平方根を避ける
public class DistanceChecker : MonoBehaviour
{
    [SerializeField] private float attackRange = 5f;
    private float _attackRangeSqr; // 2乗値をキャッシュ
    
    void Start()
    {
        _attackRangeSqr = attackRange * attackRange; // 初期化時に計算
    }
    
    void CheckDistance()
    {
        Vector3 direction = target.position - transform.position;
        if (direction.sqrMagnitude < _attackRangeSqr) // √計算なし
        {
            Attack();
        }
    }
}
```

### UI最適化

#### 画面外UI要素の制御
```csharp
public class OffscreenUIManager : MonoBehaviour
{
    [SerializeField] private Canvas worldUI;
    [SerializeField] private float cullingDistance = 50f;
    
    private Camera _mainCamera;
    private float _cullingDistanceSqr;
    
    void Start()
    {
        _mainCamera = Camera.main;
        _cullingDistanceSqr = cullingDistance * cullingDistance;
    }
    
    void Update()
    {
        // 画面外またはカメラから遠い場合はUI無効化
        Vector3 screenPoint = _mainCamera.WorldToViewportPoint(transform.position);
        bool isVisible = screenPoint.z > 0 && 
                        screenPoint.x > 0 && screenPoint.x < 1 && 
                        screenPoint.y > 0 && screenPoint.y < 1;
        
        Vector3 cameraDirection = _mainCamera.transform.position - transform.position;
        bool isInRange = cameraDirection.sqrMagnitude < _cullingDistanceSqr;
        
        worldUI.enabled = isVisible && isInRange;
    }
}
```

// 悪い例：LINQは便利だがGCアロケーションが発生
void ProcessEnemies()
{
    var aliveEnemies = enemies.Where(e => e.IsAlive).ToArray(); // アロケーション
    var closestEnemy = enemies.OrderBy(e => Vector3.Distance(transform.position, e.transform.position)).First(); // 重い

// 良い例：ループとキャッシュで最適化
public class EnemyManager : MonoBehaviour
{
    private List<Enemy> _aliveEnemies = new List<Enemy>(); // 再利用リスト
    
    void ProcessEnemies()
    {
        _aliveEnemies.Clear();
        Enemy closestEnemy = null;
        float closestDistanceSqr = float.MaxValue;
        
        for (int i = 0; i < enemies.Count; i++)
        {
            if (enemies[i].IsAlive)
            {
                _aliveEnemies.Add(enemies[i]);
                
                // 最短距離も同じループで計算
                float distanceSqr = (enemies[i].transform.position - transform.position).sqrMagnitude;
                if (distanceSqr < closestDistanceSqr)
                {
                    closestDistanceSqr = distanceSqr;
                    closestEnemy = enemies[i];
                }
            }
        }
    }
}

### フレームレート分散処理

#### 重い処理の分散
```csharp
public class FrameDistributedProcessor : MonoBehaviour
{
    private List<IProcessable> _processQueue = new List<IProcessable>();
    private int _processIndex = 0;
    private int _itemsPerFrame = 5; // フレームあたりの処理数
    
    void Update()
    {
        // 重い処理を複数フレームに分散
        int processed = 0;
        while (processed < _itemsPerFrame && _processQueue.Count > 0)
        {
            if (_processIndex >= _processQueue.Count)
                _processIndex = 0;
                
            _processQueue[_processIndex].Process();
            _processIndex++;
            processed++;
        }
    }
}
```

### メソッドインライン化

#### MethodImplAttribute活用
```csharp
using System.Runtime.CompilerServices;

public class MathUtils
{
    // 小さなメソッドの強制インライン化
    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public static float FastSqrt(float value)
    {
        return Mathf.Sqrt(value);
    }
    
    // 頻繁に呼ばれる計算の最適化
    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public static Vector3 FastNormalize(Vector3 vector)
    {
        float magnitude = vector.magnitude;
        return magnitude > 0.00001f ? vector / magnitude : Vector3.zero;
    }
    
    // 条件分岐を避けた最適化
    [MethodImpl(MethodImplOptions.AggressiveInlining)]
    public static float FastLerp(float a, float b, float t)
    {
        return a + (b - a) * t; // Mathf.Lerpより高速
    }
}
```

### Burst Compiler活用

#### 基本的なBurst使用
```csharp
using Unity.Burst;
using Unity.Collections;
using Unity.Jobs;
using Unity.Mathematics;

// Burstコンパイル対応Job
[BurstCompile(CompileSynchronously = true)]
public struct VelocityJob : IJobParallelFor
{
    // NativeArrayのみ使用可能
    [ReadOnly] public NativeArray<float3> positions;
    [ReadOnly] public NativeArray<float3> velocities;
    public NativeArray<float3> newPositions;
    [ReadOnly] public float deltaTime;
    
    public void Execute(int index)
    {
        // math.XXX関数を使用（UnityEngine.Mathfは使用不可）
        newPositions[index] = positions[index] + velocities[index] * deltaTime;
    }
}

public class BurstExample : MonoBehaviour
{
    private NativeArray<float3> _positions;
    private NativeArray<float3> _velocities;
    private NativeArray<float3> _newPositions;
    
    void Start()
    {
        int count = 10000;
        _positions = new NativeArray<float3>(count, Allocator.Persistent);
        _velocities = new NativeArray<float3>(count, Allocator.Persistent);
        _newPositions = new NativeArray<float3>(count, Allocator.Persistent);
    }
    
    void Update()
    {
        var job = new VelocityJob
        {
            positions = _positions,
            velocities = _velocities,
            newPositions = _newPositions,
            deltaTime = Time.deltaTime
        };
        
        // Burstコンパイルされた高速実行
        JobHandle handle = job.Schedule(_positions.Length, 64);
        handle.Complete();
    }
    
    void OnDestroy()
    {
        if (_positions.IsCreated) _positions.Dispose();
        if (_velocities.IsCreated) _velocities.Dispose();
        if (_newPositions.IsCreated) _newPositions.Dispose();
    }
}
```

### 重要な指針

1. **プロファイラーを活用**: Unity ProfilerとFrame Debuggerで実際のボトルネックを特定
2. **早期最適化を避ける**: 明確な問題が確認されてから最適化する
3. **メモリアロケーションを監視**: Memory Profilerでヒープアロケーションを追跡
4. **フレームレート目標を設定**: 60fps、30fpsなど明確な目標を定める
5. **デバイス固有の制約を考慮**: モバイル端末では特に慎重な最適化が必要
6. **Burstは大量データ処理に特化**: 少量データでは通常のC#が効率的な場合もある
7. **インライン化は小さなメソッドのみ**: 大きなメソッドは逆効果
8. **enum型指定でメモリ節約**: byte, short等を適切に選択
9. **switch文で分岐最適化**: 4つ以上の条件分岐ではswitch推奨
10. **データ局所性を意識**: 関連データは連続配置で配置
